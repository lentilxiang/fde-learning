## A 组 · 快答

### 第 1 题 · 判断：符号 AI 属于人工智能，但不属于机器学习

**✅ 正确。**

课程原话（1.1.1）：

> 这里要提醒一句：即使是很早期的、靠人写符号规则的「符号 AI」，也属于人工智能这个大圈，只是不属于机器学习这一支。

**为什么容易答错**：直觉上会把「符号 AI」当成「前机器学习时代的过时东西」，进而划到 AI 之外。但 AI 是一个**目标/愿望**——「凡是朝这个目标努力的技术，都算 AI」，所以「人把规则写死」也是朝着这个目标的一种努力。

**区分两种思路**：

| | 怎么让机器变聪明 | 代表 |
|---|---|---|
| 符号 AI | 人把规则一条条写死（如「体温 > 38.5 度就建议就医」） | 专家系统 |
| 机器学习 | 不写规则，喂大量数据让它自己总结规律 | 今天的 AI 主流 |

> 类比：教小孩认猫，不是给他背《猫的定义手册》（符号 AI），而是给他看成百上千张猫的照片（机器学习）。

### 第 2 题 · 四个圈从大到小

**✅ 人工智能（AI）⊃ 机器学习 ⊃ 深度学习 ⊃ 生成式 AI**

每个圈的角色（1.1.1）：

| 圈 | 课程给它的定位 |
|---|---|
| 人工智能 | **一个愿望**——让机器像人一样思考、判断、做事 |
| 机器学习 | 实现这个愿望**最主流的一条路** |
| 深度学习 | 机器学习里**最能打的一支**（用「神经网络」结构，层数堆得很深） |
| 生成式 AI | 深度学习里**最新、最耀眼的一小块**（能生成新内容） |

**要注意的两个措辞细节**：
- 深度学习之所以「深」，是因为用了**神经网络**结构，而且**层数堆得很多**——层数越深，能理解的东西越复杂、越抽象。
- 「会创造」**不是**生成式 AI 才有的能力，早期就有生成文字模型、生成逼真人脸的尝试，只是能力有限、质量不稳、谈不上人人可用。

### 第 3 题 · 三个阶段 + 第三阶段的转折点

**三个阶段，各一个动词**（1.1.2）：

| 阶段 | 时间 | 动词 | 本事 | 代表成果 |
|---|---|---|---|---|
| 一 | 约 1950s–1990s | **会认** | 识别「这是什么」 | 手写数字识别 |
| 二 | 约 1990s–2016 | **会判断** | 基于数据做决策、下预测 | 垃圾邮件过滤、商品推荐、信用评分、广告点击率、搜索排序 |
| 三 | 2017 至今 | **会创造** | 生成新内容 | 写文章、画图、作曲、生成视频 |

**第三阶段的转折点（题目要求的年份和论文）**：

> **2017 年**，论文 **《Attention is All You Need》** 提出深度学习的新架构 **Transformer**。

**这条时间线的关键节点**（记住这几个就够）：

- **1956**：达特茅斯学院会议，正式提出「人工智能」，**AI 元年**
- **1950s–1990s**：早期靠人写规则（专家系统）；AI 经历过**两次寒冬**
- **1990s–2016**：两个推手 —— **互联网普及**（第一次攒下海量数据）+ **算力变强**
- **2017**：《Attention is All You Need》→ Transformer
- **2018–2019**：谷歌 BERT、OpenAI GPT 系列
- **2022 年底**：ChatGPT 发布，两个月用户破亿，AI 出圈

> 一句话记法：**1956 提出愿望 → 2017 拿到图纸 → 2022 走进大众。**

### 第 4 题 · 「会认」阶段真正落地的标志性成果

**✅ 手写数字识别。**

出处（1.1.2）：

> 一个标志性的成果，是上世纪八九十年代的手写数字识别。以 **Yann LeCun** 等人的工作为代表，AI 第一次能比较可靠地认出人手写的数字，并被真正用到了实处——比如**银行自动识别支票上的手写金额**、**邮局自动分拣信封上的邮政编码**。

**为什么是它，而不是人脸识别？**

因为它的意义**不在「认数字」本身**，而在于它证明了：

> 机器**不必靠人写死规则**，也能从大量例子里自己总结出规律。

**这是整个机器学习的立足点。** 人脸识别、语音输入这些属于后一阶段（深度学习的成果），不在「会认」阶段的标志位置。

## B 组 · 说清概念

### 第 5 题 · Transformer 是架构还是产品？「建筑图纸」想说明什么

**前半问：架构。** 课程原话（1.2.1）：

> Transformer 是一个深度学习的**架构**，不是一个具体的产品。

**后半问：这个比喻想说明「架构 ≠ 产品」。**

> 我们可以把「架构」理解成一张**建筑图纸**。图纸本身不能住人，但按照这张图纸，我们可以盖出千千万万栋**不同的楼**。

所以：

```
Transformer  =  图纸（架构）
GPT / BERT / 混元 / DeepSeek  =  照着这张图纸盖出来的不同的楼（产品）
```

**这个比喻要你记住的一句话**：

> 模型名字听起来五花八门，但它们**本质上都是基于 Transformer 这张图纸盖出来的不同的楼**。

**自测**：有人问「GPT 和 Transformer 有什么区别」→ 答「**一个是楼，一个是图纸**」。

### 第 6 题 · 大模型为什么会幻觉？「通顺 ≠ 正确」

**一句话答案**：

> **模型的目标是「接得通顺」，不是「说得正确」——它在做选择题，不是在查证事实。**

课程原话（1.2.2）：

> 由于它只负责接出「读起来最通顺、最合理」的内容，**并不真正核实事实对错**，因此当它遇到不确定的问题时，往往不会承认「我不知道」，而是会顺着语感编出一个看似有理有据、实则并不存在的答案。

**必须记住的反直觉证据**：

> 工具返回「**上海气温一万度**」这种明显离谱的数字，模型**有时会照单全收地讲出来**，有时才会察觉不对。

**这个证据说明什么**：幻觉不只发生在「模型不知道」的时候——**即使给它接上了外部工具或资料，它也可能不核实就顺着说**。

它一口气解释了三件事：

- 为什么 **RAG 能缓解幻觉，但不能根治**
- 为什么第 4 章要专门做「评测集」和「兜底回复」——**光给资料不够**
- 为什么说「**Prompt 不是安全边界**」

**顺带记住「文字接龙机器」的另外两个天生毛病**（1.2.2，题目只问幻觉，但这两个常一起考）：

| 毛病 | 说明 |
|---|---|
| ① 幻觉 | 只求通顺，不核实对错 |
| ② 对「当下」一无所知 | 不知道自己是谁、现在几点、天气如何——这些不在它看到的文字里，也不在训练学到的旧知识里 |
| ③（附加）上下文窗口有上限 | 能读进眼的文字有长度上限；且输入越长，即使没超限也常常接得不准 |

### 第 7 题 · token 是什么？为什么按 token 计费

**token 是什么**（1.2.2）：

> token 就是模型处理文字时所切分出的**最小单位**。它可能是**一个汉字**，可能是**一个英文单词**，也可能只是**单词的一部分**或**一个标点**。

模型眼中的文字**不是一个个字符，而是一串切好的 token**；它所谓的「接龙」，就是在已有 token 串后面，不断预测并接上最合理的下一个。

**为什么按 token 计费，而不是按字数**：

> 因为模型的每一步预测和生成，基本单位**就是 token，不是字符**。

「预测下一个字」只是一种通俗说法。严格讲：

- 一个汉字可能切成多个 token
- 一个英文单词可能被拆成词根+词缀
- 标点也单独算

**字数和 token 数不是一一对应**，所以只能用 token 计量。

**两个加分点**（这两条能说出，说明你真懂了）：

1. **token 不止于文字**——可以是图像、表格、甚至声音、视频的基本单位。正因把各种复杂内容都拆成了有限的基本单位，生成式 AI 才能用「从有限选择里不断决定下一个」的统一方式，生成几乎无穷无尽的内容。**这就是它能同时写文章、画图、作曲的底层原理。**
2. **token 是实际计量单位**——「模型能处理多长的内容」（→ 上下文窗口）、「调用一次花多少钱」，通常都按 token 算。**理解了 token，上下文长度和调用成本就都好理解了。**

### 第 8 题 · 短期记忆 vs 长期记忆，以及长期记忆的本质

**两者的区别**（1.2.4）：

| | 范围 | 特点 |
|---|---|---|
| **短期记忆** | 本次会话里说过的话 | 一旦换到新对话框，之前内容**不复存在**，模型「失忆」从头开始 |
| **长期记忆** | **跨所有会话**、绑定在账号上的信息 | 无论哪天、开哪个新对话，都能延续（如「从事财务工作、偏好简洁回答」） |

**长期记忆的本质（这道题的真正考点）**：

> 所谓长期记忆，**本质上仍是把该记住的内容，在恰当的时候重新组织成文字、再喂回给模型**。

**这一句是 Day 1 最值钱的一句**，它一次说穿三件事：

| 它推翻了 | 它说明了 |
|---|---|
| ❌「模型记住了我」 | 模型**没有任何记忆**。它每次能「看到」的只有当前那次输入的文字 |
| ❌「记忆是个存储功能」 | 记忆是**一个搬运动作**：取出来 → 组织成文字 → 塞回输入 |
| ❌「长期比短期高级」 | 两者机制**完全一样**，只是记录存在哪、什么时候取回来不同 |

**⚠️ 衔接 1.3（这是最有价值的一条联系）**：

1.3 讲「**从大语言模型角度看：Agent 仍然是在'接龙'**」时，说的是同一件事：

> 我们所做的，只是把「目标是什么」「上一步做了什么」「观察到了什么结果」这些信息，**统统作为文字，一次次喂给**那个我们已经熟悉的大语言模型，让它据此接龙出「下一步应该做什么」。

**所以：长期记忆、上下文工程、Agent 循环——本质是同一种机制**。都是「把信息重新组织成文字，再喂回模型」。看懂这一层，第 3 章的 Agent 编排就不再神秘。

**自测（重要）**：既然长期记忆只是「把文字喂回去」，为什么还要单独做这个功能，每次把全部历史都塞进去不行吗？

> 答案：**上下文窗口有上限**，而且**输入越长，即使没超限也常常接得不准**。所以不能天真地把所有历史一股脑塞进去，必须**有策略地组织**到底让它看到哪些内容——这就是「上下文工程」。

**为什么短期记忆的「短」很重要**：课程给的例子很典型——用户先问「帮我算一道数学题」，接着追问「那**大 S** 是多少？」（指公式里的面积 S）。模型没记住前面在聊数学，直接蹦出「**徐熙媛（艺名大 S）**」。

> 它并不是变笨了，而是它「眼前」那段文字里，**根本没有前面聊过数学的痕迹**。

## C 组 · 应用

### 第 9 题 · Embedding 凭什么能查资料？RAG 三步

**先答「凭什么」——这是本题的核心**：

> 因为**意思相近的文字，转换出来的数字串（向量）也会很接近**。

于是：

```
「意思相近」        →  「距离近」
  语义问题             几何问题（可以用数学算）
「找相关资料」      →  「找最近的坐标点」
```

**这就是「查资料」能成立的原因**：它把「找相关」变成了「**找最近的坐标点**」——一个可计算的问题。

课程的直观例子：在二维平面（横轴=是否可食用，纵轴=是否属于动物）上，「苹果」和「梨」离得近，「老虎」离得远。**意思相近的词距离更近，意思不同的词距离更远。**

实际 Embedding 是几百到一千多维，而且**高维向量之间有代数关系**：

```
教师 − 学校 + 医院 ≈ 医生
巴黎 − 法国 + 中国 ≈ 北京
```

> 课程原话：**向量竟然学到了类比的逻辑！**

**RAG 三步**（1.2.5）：

| 步骤 | 名称 | 做什么 |
|---|---|---|
| step1 | **导入与向量化** | 提前把所有文档切分成小段（chunk），用 Embedding 把每段变成一个坐标点，存进知识库 |
| step2 | **检索召回** | 提问时先把**问题**也 Embedding 成坐标点，去知识库里找**离它最近的那几个坐标点**——这几段文字就是最相关的资料 |
| step3 | **增强生成** | 把找到的几段资料，连同问题一起**塞进提示词**喂给大模型，让它看着资料回答 |

**结论句（课程原话）**：

> 这样一来，AI 的回答就有了**准确、实时、可溯源**的依据，「幻觉」问题被大大缓解。这就是为什么**企业做 AI，第一步几乎都是搭知识库**——本质就是在为 RAG 准备「坐标点」。

**Embedding 的四个应用**（可能被追问）：① 语义搜索 ② 推荐系统 ③ 分类 ④ 聚类。

### 第 10 题 · 客服 AI 编造不存在的报销制度

这题是**场景题**，考点是「**你能不能先分流、再分治**」，不是背概念。

#### 第一步 · 先分流（别急着修）

看到「编造」，先判断是哪一支：

| 分支 | 现象 | 根因 |
|---|---|---|
| ① 资料缺失 | 知识库里**根本没有**报销制度 | 该给的内容没给 |
| ② 检索不到 | 有资料，但**没被召回** | 切分/召回参数问题 |
| ③ 查到了但编 | 资料有、也召回了，模型还是编 | **行为层**问题 |

**只想到 ① 是不够的**——这三支的修法完全不同。实际定位方法见 4.3.1「先判断：是不是知识与检索问题」。

#### 第二步 · 三层修法（课程标准答案）

| 层 | 动作 | 打什么痛点 | 出处 |
|---|---|---|---|
| **资料层** | 上传报销制度进**知识库** | 让正确内容存在且能被检索到 | 3.2 Step 7 |
| **资料层** | 加**问答对**稳高频问题 | 高频问题不再抖 | 3.2 Step 8 |
| **资料层** | 配**同义词** | 解决用户「换种说法问」 | 3.2 Step 9 |
| **行为层** ⭐ | 设**兜底回复 / 拒答** | **资料不足时明确说「不能确认」，不许编** | 3.2 Step 10 |
| **验证层** | 建评测集 + badcase 回归 | 改完确认没退化 | 4.1 / 4.3 |

**最关键的一刀是「行为层」**。课程原话（3.2 Step 10）：

> 企业应用里，**最危险的不是「回答慢」，而是「不知道却装作知道」**。拒答配置的目标，是让应用在资料不足、问题越界或风险较高时明确说明无法确认，并引导用户补充资料或联系负责人。

> ⚠️ **注意**：如果设置兜底回复，**请关闭联网搜索功能**。

**参考拒答话术**（课程原文，可直接用）：

> 抱歉，当前知识库和可用公开信息不足以可靠回答这个问题，我不能编造答案。
> 你可以尝试：
> 1. 补充相关制度、产品文档或负责人确认过的资料；
> 2. 将问题改得更具体，例如说明业务场景、适用对象和时间范围；
> 3. 如果涉及内部数据、价格、合同、客户信息或合规判断，请以正式系统或对应负责人确认为准。

**系统提示词的边界条款**也要写（3.2 Step 3，课程原话）：

> 4. 不要编造客户案例、数据、政策、价格、合同条款或内部信息。
> 3. 当问题超出知识库、公开常识或你的能力范围时，要明确说明「当前知识不足，无法确认」，并给出下一步建议。

#### 常见两条错误路线（避免踩）

**❌ 路线一：把制度写成 Skill 喂给 AI —— 概念放错容器**

课程对 Skills 的定义（2.2 中.2）：

> Skills（又称「技能」）可以为智能体应用**扩展专业能力**，例如通过**文档翻译、图像识别、语音合成**等 Skills 增强智能体的能力边界。

它扩展的是**能力**，不是**知识**。报销制度属于业务知识，该进**知识库**。

> 记法：**知识库解决「能查什么」；Skills / 工具 / 连接器解决「能做什么」。**（2.2 中.2 原话）

**❌ 路线二：做微调把制度「内置」到模型 —— 不适合注入事实**

「微调」在**整门课里只出现 1 次**，且是讲 ChatGPT 的历史成因（1.3：「ChatGPT 通过 RLHF 和指令微调，让模型第一次能稳定地听人话」），**从未**被列为注入企业知识的手段。四个理由：

| 问题 | 说明 |
|---|---|
| 治不了根 | 微调改的是**风格与能力倾向**，模型的本质仍是 token 预测（回看第 6 题：通顺 ≠ 正确） |
| 更新难 | 制度会改版，微调一次就固化，改一次要重训 |
| 不可溯源 | 答对了也说不出依据哪份文件；企业场景要的是**可引用** |
| 成本高 | RAG 只需改文档，前期搭好即可随时更新 |

## 附：Day 1 的五步能力链（1.2.8 原文口径）

```
会接龙的模型（LLM）
  → 给它人设          Prompt
  → 让它记事          Memory
  → 让它查资料        Embedding + RAG
  → 让它动手          Tool Use
  → 统一动手的规矩    MCP
```

**两个补充说明**：

- **提示词分两种**：系统提示词（System Prompt，人设与规则，用户看不到）+ 用户提示词（User Prompt，我们每次输入的那句话）。系统提示词可能超过四千个 token。
- **MCP 是什么**（1.2.7）：**Model Context Protocol，模型上下文协议**，由 **Anthropic** 在 **2024 年前后**提出。解决的是工具「各说各的方言」导致的**多对多重复劳动**问题——大家约定一套统一协议，工具方只需按标准「挂」出来一次，任何支持 MCP 的 AI 就能直接调用。

**为什么 2022 年前没有 Agent**（1.2.8）：

> 复杂、需要分步执行的长任务它仍然做不了。要突破这个瓶颈，AI 须得从**一问一答的工具**，进化成**能自己规划、分步骤把复杂任务做完的智能体**。
